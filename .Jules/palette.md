## 2025-05-14 - [Accessibility in Cloned DOM Environments]
**Learning:** This project implements dark mode by cloning the entire `.container` into a `#dark-container` for a clip-path transition. This results in duplicate interactive elements in the DOM. ARIA labels and focus indicators must be robust enough to work across both containers.
**Action:** When adding accessibility features or event listeners, use class-based selectors or event delegation (e.g., `event.target.closest`) to ensure the behavior is consistent in both the original and cloned containers.
## 2026-05-08 - [Focus Visibility in Custom Cursor Environments]
**Learning:** In interfaces where the default cursor is suppressed (`cursor: none !important`) to enable custom liquid cursors, visual focus feedback becomes the primary navigation cue for keyboard users. Relying on default browser outlines is insufficient; theme-aware, high-contrast indicators (`focus-visible`) are essential for maintaining accessibility.
**Action:** Always implement a global `*:focus-visible` rule with a distinct `outline` and `box-shadow` using theme-appropriate accent colors to ensure interactive elements are unmistakably identified during keyboard navigation.
